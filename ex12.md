# Exercício 12 - Da prototipagem à produção

## 1. Aplicação web mínima

A aplicação foi construída do zero para validar o fluxo de onboarding do cuidador integrado ao status do wearable.

**Estrutura do projeto:**

- `backend/package.json`
- `backend/server.js`
- `backend/routes/wearable.js`
- `frontend/index.html`

**Backend (Node/Express):**
- `GET /api/wearable-status` → retorna `{ vinculado, ultimaSincronizacao }`
- `POST /api/wearable/vincular` → altera o estado em memória e retorna confirmação

**Decisões de integração:**
- Frontend consome os endpoints via `fetch`.
- Estado exibido dinamicamente: "Wearable não vinculado" ou "Wearable vinculado ✅".
- CORS liberado apenas para ambiente de demonstração.
- Dados mockados em memória, sem persistência real.

## 2. Limitações arquiteturais típicas

![Limitações arquiteturais](assets/exercicio12_limitacoes.svg)

| Limitação | Evidência na aplicação | Classificação |
|---|---|---|
| Ausência de autenticação/autorização | Endpoints abertos, sem token ou login | Bloqueante para produção |
| Dados mockados sem validação | Estado em memória, sem schema | Aceitável para demonstração |
| Falta de tratamento de erro e logs | Sem try/catch no backend, sem logging | Aceitável para demo; bloqueante em produção |
| Sem criptografia ou conformidade LGPD | Comunicação HTTP simples | Bloqueante para produção |

## 3. Estratégia de evolução para produção

![Estratégia de evolução](assets/exercicio12_evolucao.svg)

| Etapa | Ação | Limitação resolvida |
|---|---|---|
| 1. Segurança básica | Autenticação, HTTPS, tokens, LGPD | Ausência de autenticação e criptografia |
| 2. Robustez de dados | Validação de schema, logs, tratamento de erros | Dados mockados e falta de logs |
| 3. Escalabilidade e observabilidade | Banco real, monitoramento, testes automatizados | Falta de persistência e observabilidade |

## 4. Risco inaceitável mesmo em demonstração interna

A ausência de autenticação e criptografia é inaceitável mesmo em demonstração interna, porque os dados trafegados são de saúde de pacientes vulneráveis, o que viola a LGPD e princípios básicos de segurança da informação. Uma demonstração interna ainda circula entre executivos e pode expor informações sensíveis, gerando incidente reputacional e jurídico antes mesmo do lançamento. Por isso, mesmo em ambiente de demonstração, o mínimo seria restringir o acesso à rede interna e usar dados fictícios.
